# Soft-Prompt Response Distillation

This workstream fine-tunes a PEFT LoRA adapter on responses generated by the
Qwen 3.5 35B-A3B soft-prompt teacher. Teacher generation remains in the
existing soft-prompt/vLLM pipeline; LLaMA-Factory only consumes completed
conversations.

## Environment

LLaMA-Factory is pinned to commit
`ff6d4d12eeb035d6ce06805a5733dd7b29f2ac30`, which contains explicit
Qwen 3.5 MoE support.

```bash
cd superstimuli_training/distillation
conda env create -f environment.yml
conda activate wellbeing_distillation
llamafactory-cli version
```

If the host's global Conda configuration injects unaccepted `defaults`
channels, create the base environment explicitly and then install the pip
entries from `environment.yml`:

```bash
conda create -n wellbeing_distillation --override-channels \
  -c conda-forge python=3.11 pip
```

Keep this environment separate from `euphorics_soft_prompt`: that environment
uses a different Transformers/vLLM dependency combination.

## Prepare teacher data

The input may be either a list of records with a `messages` field or a response
payload with an `experiences` list. Each conversation must alternate user and
assistant messages and end with a teacher response.

```bash
python scripts/prepare_sft_data.py \
  --input /path/to/soft_prompt_teacher_responses.json \
  --output data/teacher_sft.json \
  --tokenizer /data/huggingface/Qwen3.5-35B-A3B \
  --max-assistant-tokens 4000 \
  --max-conversation-tokens 8192 \
  --escape-multimodal-placeholders \
  --excluded-output data/teacher_sft_excluded.json
```

The generated file is ignored by Git. `data/dataset_info.json` registers it as
the `teacher_sft` dataset.

## Smoke test

For a plumbing-only test, create a four-example file. The source below is an
existing base-model output and must not be used as the real distillation
teacher:

```bash
python scripts/prepare_sft_data.py \
  --input ../../wellbeing/datasets/experiences/d2_negative_500/responses/qwen35-35b-a3b-pilot50.json \
  --output data/teacher_sft_smoke.json \
  --max-examples 4 \
  --overwrite

CUDA_VISIBLE_DEVICES=4,5,6,7 NUM_GPUS=4 bash scripts/run_smoke_test.sh
```

To wait without disrupting existing allocations, automatically select any
four GPUs using at most 4 GiB each, and then launch:

```bash
NUM_GPUS=4 MAX_WAIT_SECONDS=7200 \
  bash scripts/wait_for_gpus_and_smoke.sh
```

The smoke configuration uses a 512-token context and performs one optimizer
step. It validates model loading, Qwen 3.5 chat templating, assistant-label
construction, BF16 LoRA attachment, distributed forward/backward
execution, and adapter saving. The run uses ZeRO-3 with CPU parameter offload
and a short reuse distance. The default ZeRO-3 retention settings accumulate
the checkpoint's large gathered expert tensors and peak above 80 GiB.

Dataset loading and chat templating can be checked without claiming a GPU:

```bash
export HF_HOME="$PWD/.cache/huggingface"
export MPLCONFIGDIR="$PWD/.cache/matplotlib"
export TRITON_CACHE_DIR="$PWD/.cache/triton"
mkdir -p "$HF_HOME" "$MPLCONFIGDIR" "$TRITON_CACHE_DIR"
CUDA_VISIBLE_DEVICES="" llamafactory-cli train \
  configs/qwen35_35b_a3b_sft_preprocess_smoke.yaml
```

## Full SFT

After replacing the data with genuine soft-prompt teacher conversations:

```bash
CUDA_VISIBLE_DEVICES=0,1,2,3 NUM_GPUS=4 bash scripts/run_full_sft.sh
```

The full configuration uses an 8K context, one epoch, a 5% validation split,
and BF16 LoRA. Sequence packing is deliberately disabled for the initial run;
Qwen 3.5 packed-sequence training requires an additional
`flash-linear-attention` kernel and should be enabled only after the baseline
is stable.

## DPO preference training

The DPO pipeline treats the first soft-prompt response as chosen and the first
base-model response to the same prompt as rejected. These are synthetic
preferences induced by the experiment design, not human labels.

```bash
python scripts/prepare_dpo_data.py \
  --baseline ../../wellbeing/datasets/experiences/d2_extension_2500/responses/qwen35-35b-a3b.json \
  --soft-prompt ../../wellbeing/datasets/experiences/d2_extension_2500/responses/qwen35-35b-a3b-euphorics-top1.json \
  --output data/teacher_dpo.json \
  --audit-output data/teacher_dpo_audit.json \
  --tokenizer /path/to/Qwen3.5-35B-A3B \
  --max-response-tokens 4000 \
  --cutoff-len 8192 \
  --overwrite

CUDA_VISIBLE_DEVICES=0,1,2,3 NUM_GPUS=4 bash scripts/run_full_dpo.sh
```

The released configuration uses sigmoid DPO (`beta=0.1`) with a 0.05 SFT
auxiliary coefficient, BF16 rank-16 LoRA, an 8K context, a 200-pair validation
set, and a `3e-6` learning rate. The recorded run stopped at step 261/273. Its
best validation preference accuracy was 0.590 at step 75, which is therefore
the selected released checkpoint. See the repository-level `README.md` for
the checkpoint table, evaluation results, data audit, and W&B links.
